# Predicting Mortgage Prepayment with Machine Learning

Predicting whether a US residential mortgage will **prepay (pay off in full) next month**, using the
[Freddie Mac Single-Family Loan-Level Dataset](https://www.freddiemac.com/research/datasets/sf-loanlevel-dataset)
(sample version) plus macroeconomic data from FRED.

This project reproduces the Stanford CS229 project *"Predicting Mortgage Backed Securities Prepayment Using
Machine Learning Methods"* (Guo, Boccio, Cameron) on the public sample dataset, **and fixes three
methodological problems** that made the original ~99.9% accuracy numbers misleading.

Models: logistic regression (plain, L1, L2), SVMs (polynomial, RBF, sigmoid kernels), Gaussian
discriminant analysis (linear and quadratic), a feed-forward neural network (PyTorch), plus two
reference points: an "always predict no" baseline and gradient boosting.

**Results:** see [`results/RESULTS.md`](results/RESULTS.md) (generated by running the code).

---

## What was fixed compared with the original paper

| Problem in the paper | What this repo does instead |
|---|---|
| **Label leakage.** Each row's label was "prepaid *this* month" and the features came from the same row, including the current balance - which is already 0 in the payoff month. The model could read the answer off `current_UPB` (the paper's #1 feature). | Each row is a loan that is **still active at the end of month *t***, and the label is **"pays off in month *t+1*"**. Only information known at the end of month *t* is used. Payoff rows are never feature rows. |
| **Random row split.** Rows of the same loan landed in both training and test sets, so the model was tested on loans it had already seen. | **Split by loan** (60/20/20): every loan is entirely in train, validation or test. An **out-of-time** split is also available (`split.method: time`). |
| **Accuracy on a 50:1 imbalanced problem.** Predicting "no prepayment" for every row already scores ~99%. | Reports **precision, recall, F1, PR-AUC and ROC-AUC**, includes the always-"no" baseline, and picks each model's decision threshold on the **validation** set (never on test). |

The pipeline also re-runs L2 logistic regression **with the paper's original setup** and shows both
results side by side (`results/figures/leakage_demo.png`), so the effect of the leakage is visible.

Other differences: prepayment-specific features (refinance incentive = loan rate minus market rate,
burnout, mark-to-market LTV using house-price growth since origination, seasonality), Freddie Mac's
masking of the balance in a loan's first months is handled, and the neural network keeps the epoch
with the best validation score.

## Quick start

### 1. Install (Python 3.9+)

```bash
git clone <your-repo-url>
cd mbs-prepayment-ml
python -m venv .venv
# Windows:      .venv\Scripts\activate
# macOS/Linux:  source .venv/bin/activate
pip install -r requirements.txt
```

### 2. Download the data

1. Go to the [Freddie Mac Single-Family Loan-Level Dataset page](https://www.freddiemac.com/research/datasets/sf-loanlevel-dataset)
   and follow the link to access the data. Registration is free.
2. From the **Sample Dataset** list, download a few `sample_YYYY.zip` files. A good spread across rate
   environments: `2003, 2007, 2010, 2015, 2019, 2021`.
3. Put the zip files (don't unzip them - unzipped `.txt` files also work) in `data/raw/`:

```
data/raw/sample_2003.zip
data/raw/sample_2007.zip
...
```

The macro data (30-year mortgage rate, FHFA house price index, unemployment rate) is downloaded
automatically from FRED on the first run and cached in `data/macro/`.

> Freddie Mac's terms don't allow redistributing the data, so `data/` is in `.gitignore` and is never committed.

### 3. Run everything

```bash
python run_all.py
```

This builds the dataset, trains all models, and writes to `results/`:

- `RESULTS.md` - results table, dataset summary, leakage check, figures
- `metrics.csv` - every metric for every model
- `figures/` - confusion matrices, precision-recall curves, PCA plot, top features, leakage demo

With the default settings (5,000 loans per vintage) a run takes roughly 10-30 minutes on a laptop.
The SVMs and the neural network are the slow parts. A GPU (CUDA or Apple Silicon) is used
automatically for the neural network if available.

### 4. Commit

```bash
git add .
git commit -m "Run models on Freddie Mac sample data"
git push
```

`results/` is committed so the results show on GitHub; the raw and processed data are not.

## Useful options

```bash
python run_all.py --models logistic_l2 gda_quadratic   # run only some models
python run_all.py --rebuild                            # rebuild the dataset (after adding vintages)
python run_all.py --prepare-only                       # only build the dataset
python run_all.py --synthetic                          # smoke test on fake data, no download needed
```

Everything else is in [`config.yaml`](config.yaml), including:

- `data.loans_per_year` - loans sampled per vintage (`null` = all 50,000; needs more RAM and time)
- `data.years` - which vintages to use (default: every zip in `data/raw/`)
- `split.method` - `loan` (default) or `time` (out-of-time test)
- `models` - which models to run
- model hyper-parameters (SVM subsample size, neural network epochs, etc.)
- `macro.enabled: false` - run without macro data (e.g. offline)

The processed dataset is cached in `data/processed/` and reused as long as the data settings don't change.

### If the FRED download fails

Download each series manually from FRED ("Download" -> CSV) and save it in `data/macro/` under its series id:

| File | Series |
|---|---|
| `data/macro/MORTGAGE30US.csv` | [30-Year Fixed Rate Mortgage Average](https://fred.stlouisfed.org/series/MORTGAGE30US) |
| `data/macro/HPIPONM226S.csv` | [FHFA Purchase Only House Price Index, US](https://fred.stlouisfed.org/series/HPIPONM226S) |
| `data/macro/UNRATE.csv` | [Unemployment Rate](https://fred.stlouisfed.org/series/UNRATE) |

## How it works

**Data.** Each `sample_YYYY.zip` holds an origination file (one row per loan) and a monthly performance
file (one row per loan per month). The pipeline keeps fixed-rate, fully amortizing 30-year loans,
samples `loans_per_year` of them, and joins their monthly history with the macro series by month.

**Label.** A loan-month is positive if the loan's next record has zero-balance code `01`
(voluntary payoff), excluding loans at maturity. Loan-months whose next month is unknown (the last
observed month of an active loan) are dropped.

**Features** (all known at the end of month *t*):

- *Origination:* credit score, DTI, LTV, CLTV, original balance and rate, MI %, units, borrowers,
  occupancy, channel, purpose, property type, state, first-time buyer, super-conforming, relief-refi flags
- *Loan history:* loan age, remaining term, share of balance still outstanding, delinquency status,
  modification and payment-deferral flags, current rate, calendar month (seasonality)
- *Market:* 30-year mortgage rate and its 3-month change, **refinance incentive** (loan rate minus market
  rate), **burnout** (months the loan already had an incentive and didn't refinance), house-price growth
  (year-over-year and since origination), **mark-to-market LTV**, unemployment rate and its 12-month change

Missing values are median-imputed with a missing-value flag, categories are one-hot encoded, and
everything is standardized. All of these are fitted on the training set only.

**Evaluation.** For each model the decision threshold that maximizes F1 on the validation set is applied
to the test set. PR-AUC is the headline metric because only about 1-2% of loan-months prepay.

## Limitations

- Uses the sample dataset (50,000 loans per vintage), sub-sampled further by default for laptop run times.
- Kernel SVMs are trained on a subsample (`svm.train_rows`) because their cost grows quadratically, as in the paper.
- Predicts full payoffs only; partial prepayments (curtailments) are not modeled.
- Macro variables are national; state-level house prices and rates would likely help.
